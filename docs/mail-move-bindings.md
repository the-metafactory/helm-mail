# Inactive Mail move bindings

`src/adapter/moves.ts` exports `registerMailMoves` and `withMailMoves` for an explicitly provisioned adapter entry. The committed read adapter does not import or register them, and its manifest still declares only reads. No CLI move command or native-path cutover is supplied here.

The wire schema references and inputs follow the Cortex v6.30.0 move contract: `mail.move.input` receives `{ message, target: "archive" | "junk" }`, `mail.trash.input` receives `{ message }`, and `mail.restore.input` receives `{ message, from }`. All return `mail.mail.move.output` with `{ ref, folder }`, or `mail.mail.error`. The existing read declaration and canonical message references are retained.

The connection interface remains version 1. New optional `move`, `restore` and `lookupMove` methods form an additive capability. A connection missing any of them offers none of these bindings. In particular, the existing `CliConnection` remains draft-only; native CLI implementation is separate work. There is no permanent-delete operation.

Move and restore requests carry a stable request ID, account, message identity and receipt context. The provider must persist the original request and outcome, bind repeated IDs to the same input and snapshot, deduplicate concurrent calls, and retain lookup evidence for at least seven days. `lookupMove` returns that historical request and result. Receipt context contains operation, attempt and snapshot identities; a connection treats it as opaque receipt correlation, not authorization. An admitted snapshot must name the matching message target and exactly one matching account destination, as the Cortex move snapshot does. Empty, duplicate or foreign destinations are refused before a provider request. The admitted host listing supplies the account. The adapter makes no grant or prompt decision.

Restore names its expected current folder. The connection must compare that folder before any mutation, return a conflict after a later move, report missing mail and denied accounts without an effect, and restore the recorded previous folder. An uncertain response does not become a failure or trigger an automatic retry. Historical lookup can report the original outcome after a new binding instance starts.

## Unfinished release condition

This candidate is not released or activated. The public v6.30.0 conformance kit can dispatch the generic capability IDs, but its sampled snapshot omits the required message target and matching account destination. An earlier permissive candidate accepted that incomplete scope; parent review caught it, and the binding now refuses it. Unit tests verify the binding semantics with correct snapshots, including Undo, conflict, missing/denied cases and unavailable restore; those are not real-journal acceptance proof. Its generic runner does not drive a provider lookup back into the uncertain real journal: it returns reports and removes its store, while the failure suite has no reconciliation scenario. A mock-host unit lookup is not that missing proof.

Before release, a supported public Cortex verification entry must exercise timeout followed by lookup and journal settlement, with one effect, matching attempt/snapshot identity and a durable receipt after reopening. Keep Helm Mail prerequisites #22 and #26 open until that required test is possible. The host facade, grants, receipt coordinator and reconciliation implementation stay in Cortex.
