# Inactive Mail move bindings

The separately built `adapter-actions/` generation adds `mail.move`, `mail.trash` and `mail.restore` alongside reply drafts and the existing reads. Its sole export is `createDeskAdapter(host)`. The read generation in `adapter/` and its generic conformance checks remain intact. These are alternatives for the same adapter identity; activation, deployment and native-path cutover are separate work.

Cortex v6.32.0 / Desk SDK 1.13 supplies the canonical declaration, message/account schemas and approval snapshots. `src/adapter/moves.ts` composes that declaration and registers the bindings. The host selects a version-1 connection through `host.mailExecution`; the package receives only method metadata and admitted calls, with no ambient command, credential or provider configuration. Missing move, restore or historical lookup support leaves every move unavailable. There is no permanent-delete operation. `CliConnection` remains draft-only; native move CLI implementation is separate work.

`move` and `restore` requests carry a globally unique request ID, account, message identity and original operation/attempt/digest context. Historical `lookupMove` returns the saved native request and outcome. A serial repeat must return the existing outcome for the same input and conflict for a changed input; this interface does not attest a cross-process concurrency guarantee or a retention window. Connector support truthfully declares `dedup: none`. The host journal suppresses repeated dispatch of the same completed operation and does not automatically replay an uncertain operation.

Dispatch requires the matching message target and exactly one matching account destination. Restore names its expected current folder and the provider conditionally restores the recorded previous folder. A later move produces a conflict without an effect. Missing mail and denied accounts produce no effect. Timeout remains uncertain until historical lookup can settle it. Recovery compares actual saved native action, message, account, operation, attempt, digest and target or restore precondition against the immutable original host context. Initial lookup must definitively report not found before a mutation starts. Unavailable, malformed or mismatched history remains uncertain without a new mutation. Missing or mismatched evidence cannot produce success; expected context never substitutes for native evidence.

`bun run probe:moves` loads the actual committed action package through public `runMailActionScenario` and the production journal with an invented fake provider. It checks Archive, Junk, reversible Trash, Undo, conflict, missing/denied, missing restore/provider/version/methods, malformed account/message scope, uncertain repeat suppression, timeout followed by lookup and durable receipts, and altered historical evidence. Two controlled in-process loader/factory/connector/host reconstructions preserve the original attempt and digest with one effect. This does not simulate OS-process termination or prove a live native provider's implementation. The probe requests no credential and performs no real Mail operation.
