# Inactive one-click unsubscribe binding

The separately built `adapter-actions/` generation adds `mail.unsubscribe` using the public canonical declaration and snapshot. Its sole export is `createDeskAdapter(host)`. It retains reply, move, Trash, restore and read metadata; `adapter/` remains the read generation. These are alternative generations of adapter `mail`, never configured together here. No discovery, activation or native-path removal occurs.

The binding uses only admitted `host.mailExecution` methods `unsubscribe` and `lookupUnsubscribe` on version 1. The host owns provider selection, credentials, account access, approval and one-click eligibility. The binding accepts no raw URL, header, command or provider configuration. A fresh listing, exact message target and one account destination must match the public snapshot. No one-click eligibility, denied account or missing message produces no unsubscribe effect.

The versioned interface adds `UnsubscribeRequest` (`version`, `requestId`, `account`, `messageId`, immutable `context`) and `UnsubscribeResult`. Native IDs are `mail.unsubscribe:${ownerRequestId}`. Historical results have `status: found`, `action: unsubscribe`, the actual original `request`, and `result`; success binds the message/account and endpoint-derived `host`. The binding compares these against the host's durable original approval and the bounded listed host. Missing, malformed, rejected or mismatched history remains uncertain. Mutation starts only after definitive `not_found`; there is no adapter authority cache.

`FakeUnsubscribeConnection` is the Mail-owned invented-data provider for verification, not a production native CLI. It parses its own RFC one-click headers, restricts endpoint URLs to HTTPS invented `*.example.test` hosts without userinfo, fragment or non-default port, and suppresses serial repeats by account/message independently of request IDs. `FakeOneClickEndpoint` records an injected POST with `List-Unsubscribe=One-Click`; it opens no HTTP/TLS connection. No global TLS setting changes. Provider data survives controlled connector/host reconstruction in the fixture, not an OS-process restart.

`bun run probe:unsubscribe` loads the actual built manifest/backend through public `runMailActionScenario`, using production approval, journal, dispatch and recovery. It checks one effect, repeats, unavailable/denied/missing scope, malformed headers, method/version refusal and strict historical recovery. Lost-response recovery preserves original operation/attempt/digest and receipts through two in-process reconstructions. The runner's repeated operation proves host-journal suppression; its fixed synthetic owner request ID cannot prove a new press. A separate direct call to that same actual versioned Mail-owned provider uses a distinct request ID and new operation/attempt for the same message, asserts `exists`, distinct native history, and one endpoint effect. These proofs cover separate layers.

The connector declares `dedup: none`, historical lookup, no cancellation and no compensation. No concurrent native suppression or retention guarantee is asserted. The private native CLI implementation and its durable message suppression remain separate work. The package probe uses exact local confirmation. Cortex v6.32.0 `src/conversations/domain-adapters/__tests__/mail-unsubscribe-host.test.ts` separately tests the dedicated grant, irreversible warning and no-Undo/refusal receipts; this package does not claim the generic scenario executes those standing-grant cases. No sending or real Mail is exercised.
